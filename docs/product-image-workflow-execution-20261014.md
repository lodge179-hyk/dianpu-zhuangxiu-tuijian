# 商品截图到装修模板：执行与验收

日期：2026-10-14。分支：`codex/store-planning-workflow`。实施前基线：`b087151`。

## 已确认目标

用户上传包含多个商品的列表截图；可补充多张，不是店铺截图。截图用于理解商品品类和可见特点，不要求使用上传商品或还原具体 SKU。允许生成相似、同类型示意商品。只交付一套装修模板，模块组合由程序执行，AI 负责识别、检索风格和整套画面设计；视觉效果由用户上传图片验收。

## 本轮实现

1. 支持多张列表截图，按可辨识商品信息判断是否需要补充；允许单一品类，不虚构其他经营范围凑导航。
2. 通过本机已有百炼凭据接入千问：商品识别 → 强制联网检索风格 → 根据已选模块写整套素材要求。联网来源来自服务返回的搜索记录；没有来源时明确失败，禁止用模型自编链接冒充搜索。风格提案与商品事实分开保存。
3. 主流程的画面内容由 AI 动态写出，不使用美妆/服装关键词分支或统一米色默认风格；程序保留现有组件、比例、批次、裁剪与导出约束。每个任务保存识别结果、来源、选定风格、逐图设计及最终提示词。
4. 新任务可调用千问图片 API 按现有最多两批总图生成、裁剪和组装。第二批只参考第一批风格。失败停止，不自动增加付费重试；保留已完成图片，用户可以手动上传或明确重试失败批次。内置会话生图工具不伪装成网页可调用 API。
5. 页面显示各阶段进度、模型配置状态、已识别品类、来源、最终提示词、失败原因、预览与下载。新流程不复用旧美妆素材或自动套用两套导航图库。
6. 停用实验服务的旧火山/豆包调用入口。保留历史结果、离线示例、完整 JSON 导入及手动总图上传。

## 可动态优化范围

允许调整输入张数/体积上限、结构化字段、提示词、阶段划分、错误处理、进度展示、1 至 5 品类的组件选型、批次尺寸和针对性测试。可依据官方接口文档调整千问适配与联网来源解析；模型、地址允许服务端环境变量覆盖。不引入大案例库、向量数据库、复杂 Agent 框架或新的收费订阅。

本轮不修改主应用/平台组件几何、不做平台发布、不合并分支；不静默切换模型、不调用已禁止的火山模型。不用合成测试冒充真实生图效果。开发验证只用受控模型响应与合成总图，真实截图识别、搜索质量和生图效果由用户后续验证。

## 验收

- 多截图与信息不足分支可用，单一品类不会编造分类。
- 搜索确实要求联网；界面引用仅来自响应中的来源，候选链接不可执行本机请求。
- AI 只能改素材内容和视觉方向，不能增删组件、图片 ID 或比例；最终 Prompt 可查看且与实际请求一致。
- 一次新任务只生成一套；请求失败不重试，部分完成和重启中断正确保存，不重复生成成功批次。
- 旧记录、示例、手动上传、PNG/ZIP 下载不回归；敏感配置不出现在结果、日志或提交中。
- 自动化检查与浏览器验证通过后更新此文档，提交并推送现有分支，不合并。

## 全链路稳定性修复（实施前）

本次目标不再是单点补丁：复盘已发生的三类真实失败，并在识别、来源、风格、设计、生图下载、裁剪、恢复、导出各边界注入异常，跑完整工作台流程后交付。

发现：当前识别响应全局类别写“女装/裤装/上衣”，商品却写“T恤/牛仔裤”等细类；照片编号实际正确。结构契约重复表达同一关系，导致真实模型合理的层级差异被当成不存在品类。设计阶段也要求模型重写程序已经决定的比例和用途，存在同类风险。

允许范围：重设模型输出与程序职责边界，嵌套分类消除重复外键；程序注入固定比例/用途；对空白、数字字符串、重复条目、非核心说明长度等做可审计兼容；未知来源、无效图片编号、缺失画面或截断内容不猜测。识别结果超出可支持范围给出具体原因。统一保存和复用每阶段成果，所有失败/中断能从必要步骤继续；已取得图片下载/裁剪恢复不重复付费生图。界面区分继续与明确重新生图，断网只重试状态读取。

验证矩阵：新旧模型结构、跨品类样本、重复与缺省字段、ID/比例/用途漂移、JSON 引号与截断、无来源/非法来源、鉴权/限流/超时/非 JSON、图片下载失败/无效格式、分隔缺失/数量错误、部分成功、重启和导出。新增测试须使用现实响应的变化，不能只返回完全照抄实现的理想 JSON。

本次会用当前已上传商品截图进行一次实际完整联调，优先复用成功步骤，最多按计划生成两批图；不自动重复付费请求、不调用旧火山模型、不合并。真实画面审美仍交用户判断。测试和实际联调结果分开记录，不能承诺模型永远不出错。
