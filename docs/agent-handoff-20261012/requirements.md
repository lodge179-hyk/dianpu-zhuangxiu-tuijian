## 不可修改的 UI 硬约束（最新纠正，优先于下文旧说明）

可以重做实现、调整生成方式，但不能重新设计已确认的页面结构。先阅读 `scripts/decoration-mvp/current-page-spec.md` 与 `scripts/decoration-mvp/layout-acceptance.md`，以这两份已确认规格为边界。

页面顺序必须是：**双绿色三角招牌及平台操作栏 → 会员权益／积分商城 → 四个圆形导航 → 4:3 轮播 → 三列竖向海报 → 三列商品橱窗**。

- 招牌保留固定双绿色三角背景、已确认比例及平台操作栏；仅替换店铺名称、头像等可变内容，不能换成紧凑极简头部或删除控件。
- 权益区保留浅色薄横条、小号橙色线框徽标／礼物图标、文字和箭头，不改成大营销卡片。
- 导航保留四个等大正圆图片，文字在图下；不能改成文字标签或移到轮播后。
- 轮播为 4:3、左右贴边、四角直角、指示点在图片内；不另加标题条或指示点条改变结构。
- 海报固定三列，等宽等高、竖向约宽:高=1:1.3，整行贴边；轮播与海报之间、海报之间仅细白线，不能增加宽留白或换成推荐卡片。
- 商品橱窗固定三列，图片为正方形，名称在图下，购物车在每卡信息区右下方；未知价格留空，不能改成双列目录或删除购物车。
- 大模块和每个小组件都要命名并落实尺寸、位置、内容来源和溢出约束。AI 仅在指定装修区域内设计风格、选品和视觉内容，不能自行变更模块格式、列数、顺序、控件或间距。
- 近似比例和精确平台规格要区分，不把本轮近似目标冒充所有格式的通用规定。可复用或拆分生成并拼接，但必须还原上述确认结构。


## 可直接发送给接手 Agent 的任务

请实现一个面向普通商家的 AI 店铺装修 Demo。用户只上传一张当前店铺截图，应用自动理解店铺与商品、决定合适的设计方向、复用普通素材、生成需要设计的区域，并交付完整装修效果预览和下载。

从整体流程出发处理问题，不要只围绕某个报错反复打补丁。大模块及其内部小组件都需要明确命名、职责、内容来源、位置和尺寸约束。可以拆分生成后组合，不要求一次模型调用完成整张页面。不要让用户填写风格，也不要让用户参与中间 Prompt、裁切、拼图或任务路径传递。

已有上下文足够，不要反复确认；先完成 Demo，再让用户集中试用。用户允许不完美，但要求真实说明完成情况，不能用假结果、旧结果或降级结果冒充新生成。你可以评估后复用、调整甚至重做实现，但不要破坏本地密钥、历史素材或仓库权限约束。

**用户已明确把测试交给自己：不要运行测试、验收、批量实验或主动调用模型生图。可以阅读、修改实现，并启动或重启必要服务供用户使用；重启前不要中断用户正在执行的生成任务。**

当前最新问题：用户上传截图后，结果显示“这次生成未完成”，错误为“商品局部坐标无效”。请纳入完整流程处理，具体原因需要结合任务记录核实，不能只隐藏错误提示或直接宣布模型不行。

## 用户真正要验证什么

用户希望验证：不需要自己懂设计，只提供现有店铺信息，应用就能给出一张包含商品、UI 结构合理、整体视觉可接受的完整店铺装修效果图。

当前先验证效果预览，不要求真实店铺发布、点击跳转、生产级商用、多品类全面适配等后续能力。不要在基础 Demo 未跑通时，把这些后续问题当成主要阻碍。

“一次提交获得完整结果”是当前产品目标。“必须一次生图生成全部内容”是早期技术路线，已经允许调整。

## 用户明确要求

### 输入尽可能少

- 入口只需要上传当前店铺截图。
- 不显示“想要的风格”，包括选填也不要。用户认为普通商家不知道应该怎么描述风格，应由应用判断。
- 商品品类、可见商品、店铺内容和设计方向尽量自动识别，不让用户先填写一套设计参数。
- 能从上下文、已有抓取资料或截图查到的内容，不要求用户重新提供。
- 只有确实无法完成判断时，才提出最少的必要补充，不能把正常内部处理转嫁给用户。

### 生成方式可以调整

- 可以分成几部分生成，最后组合成完整页面。
- 不必所有元素都 AI 生成。导航、品类入口及通用内容可以复用现有素材。
- 重点生成海报和真正需要视觉设计的区域。
- 需要完整、协调的页面，不能各部分单独好看，最后组合不上。

### UI 约束需要到小组件

- 大模块要命名，内部小组件也要命名，不能只给一个大区域名字。
- 对每个区域说清楚是什么、负责什么、放什么内容，以及允许改变和必须固定的部分。
- 名称用于明确职责，布局约束用于避免位置、间距、比例反复偏移。
- 示例层级：商品橱窗 → 商品卡片 → 图片区、名称区、信息区、购物车；导航 → 单个入口 → 图像、文字。
- 这些是职责要求，不要求照抄某一套英文 ID。

### 交付方式和工作节奏

- 先做完整 Demo，让用户一次性试用；不要让用户持续卡在零散实验中。
- 已经理解的事情直接做，不要一直问是否继续。
- 用户允许不完美，但不接受忽悠、敷衍、虚假完成或只口头承诺。
- 不只是附和用户或 Leader，需要提出自己的判断并落实。
- 从整体体验出发，没必要的操作步骤可以删；必要时可以重做实现，但不能改动已确认的页面结构或删去平台控件。
- 最新约束是“测试交给我，你别测了，很拖时间”。不要继续执行此前的自动测试或生图验证计划。

## 历史实验的必要背景

最早尝试让模型一次直接生成完整装修图，固定三组商品和招牌、导航、轮播、商品橱窗等结构。两轮正式测试分别是 0/3 同时通过 UI 与商品严格验收；第二轮采用抓取数据渲染的布局参考后，部分比例改善，但仍有几何偏差及商品配件遗漏。

这两轮使用会话内置生图工具，不是当前 Demo 中的 Seedream 调用，不能直接混同模型能力。

后来用户暂时放宽商品细节要求，并接受拆分、复用素材、固定布局的方向。因此，不能直接把旧口径 0/3 当成新版 Demo 的通过率。原先“固定输入生成三次，至少两次合格”只是历史实验门槛；用户现在要求 Agent 不自行测试。

更早的模块化路线有部分页面被认可，但同样不代表当前截图输入 Demo 已验收通过。
