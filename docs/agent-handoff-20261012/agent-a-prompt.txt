## 不可修改的 UI 硬约束（最新纠正，优先于下文旧说明）

可以重做实现、调整生成方式，但不能重新设计已确认的页面结构。先阅读 `scripts/decoration-mvp/current-page-spec.md` 与 `scripts/decoration-mvp/layout-acceptance.md`，以这两份已确认规格为边界。

页面顺序必须是：**双绿色三角招牌及平台操作栏 → 会员权益／积分商城 → 四个圆形导航 → 4:3 轮播 → 三列竖向海报 → 三列商品橱窗**。

- 招牌保留固定双绿色三角背景、已确认比例及平台操作栏；仅替换店铺名称、头像等可变内容，不能换成紧凑极简头部或删除控件。
- 权益区保留浅色薄横条、小号橙色线框徽标／礼物图标、文字和箭头，不改成大营销卡片。
- 导航保留四个等大正圆图片，文字在图下；不能改成文字标签或移到轮播后。
- 轮播为 4:3、左右贴边、四角直角、指示点在图片内；不另加标题条或指示点条改变结构。
- 海报固定三列，等宽等高、竖向约宽:高=1:1.3，整行贴边；轮播与海报之间、海报之间仅细白线，不能增加宽留白或换成推荐卡片。
- 商品橱窗固定三列，图片为正方形，名称在图下，购物车在每卡信息区右下方；未知价格留空，不能改成双列目录或删除购物车。
- 大模块和每个小组件都要命名并落实尺寸、位置、内容来源和溢出约束。AI 仅在指定装修区域内设计风格、选品和视觉内容，不能自行变更模块格式、列数、顺序、控件或间距。
- 近似比例和精确平台规格要区分，不把本轮近似目标冒充所有格式的通用规定。可复用或拆分生成并拼接，但必须还原上述确认结构。

## 产品目标

普通商家上传一张当前店铺截图，应用自动理解店铺和商品、决定合适的设计方向、生成必要的视觉内容，最后交付一张完整店铺装修效果图，可预览和下载。

用户只需要上传截图和查看结果，不应该先懂设计、懂Prompt、懂模块规格。

先跑通一个小而完整的Demo。我允许不完美，但不能敷衍、编造结果或把“实现了代码”说成“已经验证成功”。

## 明确需要改进的内容

1. **只有截图输入。**不要提供风格选择、风格描述，连选填也不要；不要要求用户先填商品列表、选择尺寸或配置模块。应用自行分析可见信息并选择设计方向。
2. **支持长截图。**不要把所有页面内容强行塞到一次图片生成里。可以在内部切分识别，拆分生成后组合；上传、缩放、裁切和拼接尽量由应用处理。
3. **不是所有元素都要AI生成。**导航、分类入口和普通商品素材可以复用；重点设计海报等视觉区域。各部分需要遵循同一个设计方向，组合后协调。
4. **约束到小组件。**大模块、内部图片、文字、按钮、图标等都应有清晰名称和职责，明确内容来源、固定边界与允许变化的部分。不能只给大模块起名，里面仍任意挪动。
5. **完整流程一次交付。**提交后自动完成到预览和下载，不让我把任务路径发给助手、手动传Prompt、逐模块操作或拼图。
6. **整体思考。**不要只盯单个错误反复补丁。评估从截图输入到交付的完整流程，非必要的操作步骤可以删；认为合理也可以重做实现，但不得删除已确认的页面模块及小组件。
7. **失败要可理解。**明确告诉用户哪一步未完成。复用原图、备用预览或其他降级方式必须注明，不能冒充AI生成成功。不要无上限重试消耗费用。

用户真实遇到过两个问题，设计时要考虑：

- 正常上传长截图被误报“上传内容超出限制”，错误没有区分文件大小、数量和程序判断。
- 首次识别成功后，局部定位返回不符合预期，整项任务终止，提示“商品局部坐标无效”。

这里不指定具体修复函数，但你需要稳妥处理模型返回格式、坐标单位、商品编号、边界及局部失败。不要猜测未知单位，不要把不同商品错配；可以保留已有可靠结果继续，但要明确其不确定性。缺少有效输入时不能编造商品。
