# 路线 B：基于真实数据的程序 UI 复刻

交接对象：用户即将开启的新会话。先读共同需求，再自主实现一个可试用的 Demo。

## 1. 本路线验证什么

利用真实网页的模块、内部组件和样式数据，验证程序能否稳定组合、显示、导出店铺装修 UI。

第一阶段使用已有图片引用或清楚标注的本地占位素材。无需生图、无需配置模型、无需重新设计店铺风格，也无需先打通截图识别流程。

不要替用户决定整页生图路线失败；A 会独立验证。你只需交付本路线结果和边界。

## 2. 先做好工作区隔离

这是用户明确要求，不能仅靠约定“不同时编辑一个文件”。

1. 原目录 `H:\店铺装修推荐` 只读。先读取交接资料，随后复制资料到自己的工作目录。
2. 优先使用 `H:\店铺装修推荐-ui-rebuild`；存在时先检查归属，不清空、不覆盖。必要时选择新的后缀目录并报告。
3. 在独立目录创建项目，或建立独立 Git 克隆。不要通过 junction、symlink、共享 node_modules 等方式让两个工程相互写入。
4. 如从原仓库克隆，只能获得提交历史中的文件；本次数据包需单独复制。GitHub 历史仓库也不能替代本次资料。
5. 自己安装依赖和维护锁文件，不在原目录执行安装、格式化、Git checkout/reset/clean、提交或修改配置。
6. 使用独立端口，建议 5191；检查占用后决定，不占用或重启 5181。
7. 只管理自己启动的进程，不执行停止全部 node／浏览器进程的命令。
8. 不需要也不复制原 `.env.local`；不推送、不部署、不更改仓库公开状态。

如果新会话的环境不允许写入独立目录，先完成自己可访问目录中的独立项目，不回写原工程；如确实无法建立任何隔离工作目录，再说明具体限制。

## 3. 数据入口

- `data/ui-component-registry.json`：23 种格式、24 个实例，每个模块内含已命名的小组件、父子关系、矩形、展开样式和图片引用。
- `data/comparison-case.json`：第一轮比较使用的小型组合，A/B 共用。
- `data/upload-format-index.json`：历史编辑页显示的格式名称和上传建议；里面的示意图坐标不是前台 UI 尺寸。
- `data/evidence/`：本次后台名称证据和采集覆盖说明。
- `data/README.md`：坐标、视口、隐藏节点及历史差异说明。

这些是只读证据。实现中建立自己的语义化组件和规则，不直接修改证据 JSON 来迁就输出。

## 4. 最小交付

### 先完成共同样例

按 `comparison-case.json` 展示：默认招牌、四图导航、三列海报、中图轮播、单行三列商品橱窗。

这是为对比技术路线而选取的实测模块组合，不是修改原 Demo 的产品标准。模块顺序沿用第一轮实测相对顺序；仅抽取代表模块，商品橱窗取第一行三个商品。

- 参考逻辑宽度为 483px，先把这个宽度还原清楚，再处理其他宽度。
- 默认招牌实测高 258px；不要因上传建议 1080×720 而改写。
- 四图导航本次样本是无标签状态，不自行补标签；另有五列带文字样本可供后续扩展。
- 三列海报本次为方形槽位；不沿用旧样板的竖向近似值。
- 中图轮播为 4:3，没有指示点。
- 橱窗图片为方形；标题、价格、分享和购物车按样本状态分别处理。
- 不添加权益栏、营销横条、浏览器边框或页面后面的全部商品列表来填空。

### 可操作的 Demo

- 能查看整页及单个模块，标明当前使用的格式名称。
- 输出完整预览 PNG。
- 按每个实际图片槽位提供素材下载／映射；第一阶段可以下载原有素材或占位素材，必须标明来源。
- 页面中的 UI 标签、价格等与图片素材分别管理。三列海报对应三张素材，不只交付整行切片。
- 提供一份简单装修清单：模块类型、顺序、图片文件与上传槽位对应关系。
- 素材引用失效时保持布局可用并标注缺图，不凭空声称已下载原图。

没有要求本轮开发完整通用设计编辑器、AI 选款系统或所有 23 种格式。共同样例能完整跑通后，再补样式查看入口及其他模块。

## 5. 对实现方式的要求

可以使用 HTML/CSS、SVG/Canvas 或现有渲染库。选择最短、可解释的实现，不为了复用库而先引入完整 Canva 类编辑器。

- 以实测样式和几何为依据，保留模块及小组件命名。
- 在目标宽度下重建布局规则，不简单按截图坐标画一个不可解释的大背景图。
- 父元素隐藏时不渲染后代；父元素零高度与后代定位可见要分别处理。
- 字体差异、图标来源缺失、舍入、文本高度等会影响还原，记录实际差异。
- 图片 `object-fit`、裁切位置、圆角与文件原图尺寸分别处理。
- 生成的整体预览和下载素材应引用同一份资源，保证映射一致。
- 不把上传建议分辨率与实际导出的原生分辨率混淆；放大输出须注明。

## 6. 工作节奏和验收

用户希望一次性试用完整 Demo。不要不断要求用户参加中间实验，不跑大批自动测试，不调用模型。必要的构建和启动可以完成，但不得把“构建通过”当成“UI 已完全还原”。

由用户集中检查：

- 模块顺序、数量、列数和主要比例是否匹配。
- 小组件是否遗漏、额外增加或明显移位。
- 轮播无指示点；商品列表和视频没有混入。
- 每个下载文件与预览槽位能否一一对应。
- 页面长图是否完整，文件是否可打开。

交付时报告：独立工作目录、分支（若有）、访问地址、启动方式、已实现模块、素材来源、导出文件位置和已知差异。全部报告写在自己的工作目录。
