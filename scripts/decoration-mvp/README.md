# 装修预览最小脚本

Windows PowerShell 5.1 + System.Drawing；无需启动网页、数据库或安装新依赖。目前固定3件商品、4+5+5导航、三张海报、一张轮播及三张商品卡片。输出1200×3976 PNG，不是可点击小程序。

## 快速运行

在项目根目录执行（每次使用新的输出目录）：

```powershell
& .\scripts\decoration-mvp\run.ps1 -Config .\scripts\decoration-mvp\example.json -Mode Render -OutputDir .\output\decoration-mvp\my-preview-01
```

结果在输出目录的 preview.png，执行耗时和人工检查项在 run.json。示例复用已验收场景，不产生生图调用。源文件及之前结果不会被覆盖。

## 更换输入

复制 example.json 后修改：nickname（昵称）、avatarPath（头像文件，可空）、avatarText（无头像时的文字）、products（恰好3件商品，各有name/image/price）。price是自己提供的展示价格，可空，脚本不估价。image路径相对于配置文件，或使用绝对路径。reference可指定供AI参考的另一张原图。

crop 可省略，默认居中正方形裁切；手动指定格式为 [x,y,width,height]，必须正方形且不越界。不会拉伸或加白边，须检查商品有无被裁掉。posterCrops是3个场景正方形裁切坐标；换场景后删除旧坐标使用默认，或重新填写。navigation可提供14个导航名称，长名称会省略。

兰蔻示例未写色号，因源素材宣传字313与盒身315冲突；示例价格取原图促销文字，只供布局演示，不代表实时售价。源商品照片内自带的促销字不会自动清除。

## 新场景流程

1. 修改商品配置，执行同一脚本的 -Mode Prepare，输出新的准备目录。
2. 将 scene-prompt.txt 和 references.json 对应的图片交给当前会话的内置生图工具，由助手调用生成。Prepare本身不生图，也不收费调用外部服务。
3. 把生成图片保存到项目，填写原配置的 scene，执行 -Mode Render 到另一个新目录。
4. 人工检查商品身份、小字、裁切、昵称、价格后再采用。

本版是“准备 → 会话生图 → 脚本合成”，不是无人值守的一键AI生成。内置工具不能从独立PowerShell脚本直接调用；尚未接入生图API。

招牌使用已清理的固定三角背景。原昵称遮挡区仍是之前的局部背景近似恢复；其余平台控件来自截图，并非动态平台数据。

## 浏览器入口
在项目根目录运行：node scripts/decoration-mvp/web.mjs，然后打开 http://127.0.0.1:5180 。仅本机访问。选择3件商品、填写昵称/名称/价格，头像选填；可选择靠上/居中/靠下裁切。没有场景图时准备素材包，有4:3场景图时合成并下载PNG。页面本身不会调用生图模型。结果保存在 output/decoration-mvp/web-runs，每次新建目录。刷新页面后需重新选择文件，旧结果仍在本地目录中。


## 当前网页流程：整页直生成
网页入口已替换旧场景合成流程。支持轮播/三海报/商品橱窗三个模块各一次、任意顺序、两列或三列商品；顶部招牌/权益/四导航固定。提交准备整页生图任务，助手根据result中的提示词与参考图调用模型。网页不会自动调用模型；生成结果可在右侧打开查看，不进行拼接。命令行旧合成脚本保留，仅供历史实验。
