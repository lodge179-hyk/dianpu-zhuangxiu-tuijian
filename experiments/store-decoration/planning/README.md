# 呈境 · 店铺装修工作台

当前 UI 使用 studio v2：上传商品照片或列表截图 → 选择品类/风格/必含模块/商品保真 → 商品识别 → 整页创作 → 一次完整修订 → 原生组件编译 → 图文一体生成、裁剪 → 长页预览及下载。一轮产生一套方案。用户指定必须出现的大类，AI 可从完整目录补充其他组件，自行决定数量、规格与叙事顺序。

当前实现、运行路径和约束见 [项目交接](../../../AGENT_HANDOFF.md)。本目录是实际工作台应用，沿用已有平台组件几何。历史依据见 [旧流程执行文档](../../../docs/product-image-workflow-execution-20261014.md) 与 [结构执行文档](../../../docs/store-structure-execution-20261014.md)。

## 使用与设计契约

1. 上传 1–6 张 PNG/JPEG/WebP；每张最多 10MB、合计 30MB，宽高至少 80px，每张最多 6000 万像素。支持点选、拖拽、粘贴、逐张移除及全部清空；一件清楚的商品也可开始。完成后清空换图即可再生成，无需刷新；打开历史任务可沿用已保存商品图生成新方案。
2. 选择通用、珠宝、数码、服装、鞋履、香氛或箱包。每类提供 AI 推荐和 3 个专属风格，风格包含色彩、构图与图像形式。
3. 必含模块在折叠设置中勾选：招牌、分类导航、轮播与横幅、主题海报、商品橱窗、文字说明。招牌必备，默认另选轮播；每个勾选大类必须出现，未勾选仍可由 AI 加入，不再要求额外勾选图片大类。
4. 保真关闭时使用经营范围内的创意示意。开启时严格绑定识别到的原商品，并将原图实际附到创作、修订及生图请求；仍是 AI 参考重绘，不能保证像素级复刻，商品细节由用户验收。
5. 新方案包含 16–24 个模块、至少 3 个内容章节，按原生 483px 宽度计算至少 4800px 高；最多 40 张素材、10 批总图，每批最多 6 格。通过内容分工增加丰富度，不拉长图片或重复凑数。横向滑动的图数不会虚增纵向高度。预览显示实际长度，桌面目录可跳到对应章节。
6. 3:1 短轮播可作章节 banner；海报、导航、细节和商品浏览按用途设计，不固定三格海报骨架。公告仅用于有依据的公告内容。文字与画面交给图片模型共同构图，程序不再覆盖白板或追加文字；ZIP 附设计文案供核对实际字形与准确度。带文字的画面裁剪最多损失 3%，超出后在既有范围内保留整幅并补底，超限仍停止。
7. 页面展示实际阶段及素材完成数。关闭页面后可从历史任务恢复；临时状态读取失败不重新提交付费请求。失败后由用户明确继续，优先复用已存图片；只有明确选择重新生成未完成批次才放弃该批缓存。

正常 studio v2 流程有三次规划请求（识别、创作、修订）及至多十次图片请求，无额外联网风格搜索、自动生图重试或视觉评审循环。创作与修订使用 40000 tokens 输出上限以容纳长页。任务保存 `visualProfile.studio` 与 `plan.studio`，继续时保持原设置；改变设置需创建新任务。studio v1 继续保留 8–16 模块/24 图/6 批、未勾选不加入与程序合字行为，不静默升级旧任务。

保真模式的已保存修订稿若只缺局部商品引用，用户继续时仅修复对应画面，不再重写整页。模型选择已定义款式并修正构图，程序按其 `sourceEvidenceId` 关联原图，合并后仍校验完整方案；有效局部结果按原稿签名复用，非法或越界修改停止，不增加自动重试。日志保存为 `reference-repair-*`；商品选择未明确前仍不能生图。

新版请求：`POST /api/plan` 接收 `{mode,options:{modules,styleId,preserveProducts,shopName},images:[{name,data}]}`。`GET /api/config` 提供可选项，`GET /api/runs` 提供最近任务，`GET /api/runs/:id` 查询状态。省略 `options` 的旧调用保留原路径，不自动升级旧任务。

## 启动与配置

在本目录执行 `npm ci`、`npm start`，打开 `http://127.0.0.1:5182`。结果默认写入被忽略的 `output/runs/`。`PLANNER_PORT` 和 `PLANNER_OUTPUT_DIR` 可覆盖端口和输出位置。

`npm start` 读取仓库根目录本机 `.env.local`，也可直接设置进程环境变量。密钥仅在服务端使用，不进入前端配置、素材 ZIP 或 Git。

| 配置 | 用途及默认值 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 必填，百炼 API Key |
| `PLANNER_VISION_MODEL` | 商品识别、内容规划与逐图设计，默认 `qwen3.5-plus` |
| `PLANNER_SEARCH_MODEL` | 仅旧流程联网搜索使用，默认 `qwen-plus` |
| `ARK_API_KEY` | 火山方舟生图密钥 |
| `ARK_IMAGE_MODEL` | 原生图模型 `doubao-seedream-5-0-pro-260628`，其他值会明确停止 |
| `ARK_IMAGE_ENDPOINT` | 默认 `https://ark.cn-beijing.volces.com/api/v3/images/generations` |
| `PLANNER_DASHSCOPE_BASE_URL` | 百炼服务根地址，默认 `https://dashscope.aliyuncs.com`，不要带 API 路径 |
| `DASHSCOPE_WORKSPACE_ID` | 可选，未覆盖根地址时使用北京业务空间域名 |

模型与凭据需属于同一地域，并已开通对应模型权限。配置存在不表示已验证账户额度或真实调用。识别与整页规划使用百炼，生成图片使用火山 Seedream 5 Pro；不会静默回退到其他图片模型。无配置时工作台明确提示，已有成果仍可查看和下载。本机目前使用 5184；准确启动路径见项目交接。

## 旧版流程（仅供恢复历史任务）

以下为未使用 studio 的早期通用路径；新版七品类不按此流程检索风格。珠宝及其他旧 campaign profile 的三次规划路径见项目交接。不要将旧预算、原界面入口与新版工作台混淆。

1. 添加 1 至 6 张商品列表截图，可分次补充或移除。每张最多 10MB，合计 30MB，支持 PNG/JPEG/WebP。长截图提供概览及上下局部给识别模型。
2. 识别可见商品、1 至 5 个经营品类、证据图片和不确定信息。商品嵌套在所属分类下，不再要求模型填写两份可能冲突的分类关系；兼容旧响应、数字字符串和重复条目，未知图片编号不猜测。至少两种可辨识商品或款式才继续；单一品类有效。信息不足会提示补充，不为凑导航虚构品类，也不自动搜索或生图。
3. 单独调用联网搜索。只接受服务返回搜索记录中实际存在的来源；没有来源时停止。先保存服务返回的完整来源列表，再让模型只从提供的编号选择一个视觉方向，URL 由程序回填；不采用搜索模型在回答中自行写出的链接。风格选择只取得来源标题与网址，不把未读取的网页正文或图片细节说成事实。
4. AI 先规划整页主题、内容段落、用途与主次，每张正文画面引用识别阶段的商品证据编号。程序核对全部品类覆盖、重复画面、最多两个必要标题与12张素材预算，再按内容数量、主次和浏览方式选择固定海报、组合海报、橱窗等组件。主视觉支持横幅、横图和竖图，招牌可选极简或独立氛围背景。随后 AI 为程序确定的图片 ID 写画面提示词；比例、用途与主视觉位置由程序注入。内容提纲、组件选择理由与实际提示词可查看。
5. 生图接口每批返回一张总图，最多两批。第二批附第一批总图，仅作为风格参考。实际发送的完整提示词可在页面展开查看；请求使用 Seedream 5 Pro 的单图接口、明确宽高及 Base64 返回，不发送千问专用参数或不支持的组图参数；记录的提示词与请求中的 prompt 相同，服务内部处理不作保证。
6. 检测洋红分隔带，验证整批后再填入模块。新流程对比例偏差较大的图片保留完整画面、补足色板背景，留边不超过最终面积 55%，并提示检查；旧任务仍沿用原裁剪规则。格子数量错误、分隔不清或偏差超限仍停止。失败不自动重试，保留已完成素材、已收到总图及下载地址。“继续未完成素材”优先复用图片；图片已生成但下载失败时只重下。只有明确点击“重新生成失败批次”才放弃缓存重新付费生成；也可手动上传总图。
7. 素材填齐后下载完整 PNG 长图或素材 ZIP，由用户判断图片与页面效果。

一轮正常任务包含五次语言/视觉模型请求（识别、搜索、选风格、内容规划、逐图设计）和一至两次生图请求。界面展示阶段、商品理解、联网来源、选定风格、提示词、已填入素材和失败原因。关闭页面后服务仍执行，使用 `/?run=任务编号` 可查看保存进度；服务重启会标记中断，不自动重新调用。任一规划阶段失败且输入已保存时，可点击“沿用已有资料继续”，复用有效识别、来源、风格、内容规划和画面设计；画面设计缓存同时核对完整结构签名，从必要步骤补做；不重新上传截图。浏览器断网或状态接口临时失败只重读状态，不重复提交付费任务。

本地每个任务保留输入图片、识别与风格 JSON、逐阶段指令/响应、调用结果、方案、实际生图提示词、原总图和裁剪记录。只向浏览器开放必要结果文件，调用审计与响应文本不在静态下载白名单内。

## 模块与旧功能

沿用现有23种组件目录，新商品截图流程由内容提纲驱动选择；旧两种组织规则仅保留在离线示例和手填入口。支持1至5个品类。四、五品类可以使用带文字导航，少品类不补造分类。四品类约8至12模块只是提示词参考，不是硬下限；程序不会为数量增加重复大图。主视觉、正文和招牌使用独立素材。橱窗标注品类示意，价格留空。视觉重点不能冒充真实主推或销量排序。

旧任务及素材不改写。已有美妆示例、导航图库、离线试排、JSON 导入和手动图片的底层接口保留，新工作台不再展示这些历史实验入口。

`POST /api/plan` 接受 `{images:[{name,data:"data:image/png;base64,..."}]}`，返回 202 和任务编号；兼容单张原始图片请求。`GET /api/runs/:id` 查询进度。`POST /api/runs/:id/generate` 明确继续缺失批次，默认复用图片，可传 `{regenerate:true}` 明确重生未完成批次。`POST /api/runs/:id/resume` 继续失败的规划，旧地址 `/resume-research` 兼容。原推荐示例、手填资料、导入与下载接口仍保留。

## 下载

素材填齐后可下载完整 PNG 长图（2 倍清晰度）或素材 ZIP。下载不调用 AI。未完成任务、缺图或占位图阻止导出；重新填图后下载使用新内容。

ZIP 包含按模块/槽位编号的 PNG、模块文字说明、中文 CSV/JSON 对照及可离线打开的 `店铺预览/shop.html`。studio 另保留风格、模块、保真设置与原商品编号映射，文字模块提供平台文字。复用图片按各模块分别提供。这是手动装修素材包，不是平台一键导入格式；头像仍为占位图。原始截图、模型响应、本机配置和总图不进入 ZIP。

PNG 用 `playwright-core` 启动独立无头浏览器，不接入用户会话。自动尝试本机 Chrome、Edge、Playwright Chromium；部署时可设置 `PLANNER_BROWSER_PATH` 或执行 `npx playwright-core install chromium`。浏览器不可用时会说明原因，ZIP 仍可用。

## 验证与边界

运行 `npm test` 检查新旧契约、参考附件、分批、排字、导出、HTTP 工作流与恢复；`npm run test:ui` 用独立无头 Chrome 检查桌面/手机操作与请求选项。测试默认拦截全部外网 fetch，UI 提交由本地受控响应拦截，不消耗真实模型额度。界面截图保存在 `output/studio-ui-proof/`。测试不证明真实生成的视觉质量，用户明确保留生图验收。

- AI 负责商品理解、用户所选风格内的整页内容与画面设计；程序守住模块选择、商品来源、组件、比例、批次、裁剪与导出。
- 不支持任意 HTML/CSS 或坐标。studio v2 使用上述 16–24 模块/4800px 最低实际高度/40 素材/10 批预算；历史路径保持原预算，不要求用满。
- v2 不设图像形式数量配额、不强制色板逐字匹配，也不强制每批同一摄影母图。保留商品来源、必含模块和真实组件几何，模型可按主题选择摄影、线描、图标、拼贴等形式。
- v2 画面描述须非空且有实际构图信息，不以 20 字门槛判断质量；主体、原商品引用、机位和构图分工仍分别校验。已提供的整页案例可以作为设计语言参考，附件明确禁止照搬整页网格、商品和控件；未提供的参考 ID 仍拒绝。缓存修订稿符合要求时直接复用，存在实际商品来源问题时才进入必要修订。
  - 分隔带、图片数量、过度裁剪且留边适配也超限时明确拒绝。没有商品语义定位，原图本身缺少的主体不会补画。留边适配保留内容，但不能替代正确构图。
  - 分隔检测统一处理连通网格、独立闭合框和浅色外边距。分隔色偏玫红或不均匀时，先核对整批行列布局，再从实际边框取样校准；单格图也检查边界，避免行数碰巧正确却带入边框。淡粉压缩残边仅在已确认边框旁的外侧四像素内清理，不将粉色商品或背景扩散识别为分隔线。仍严格核对总格数及每行格数，不猜裁剪位置。已保存总图可重新本地裁剪，无需因此重生。
- 共享风格与参考图只提供引导，不能保证模型输出一致。识别准确率、风格适配度、生图质量和真实模型权限由用户后续用截图验证。
- 已接入原商品图片参考和来源约束，尚未实现商品像素级复制、平台发布、分类跳转或经营数据接入。

## 主要文件

- `studio-config.cjs` / `studio-contract.cjs` / `studio-contract-v2.cjs`：版本化选项、品类预设与整店设计要求；`studio-layout.cjs`：实际组件高度；`studio-batches.cjs` / `studio-generation.cjs`：新版分批与生成提示。
- `product-references.cjs`：原商品像素附件；`studio.js` / `studio.css` / `index.html`：新工作台；`studio-contract.test.cjs` / `studio-ui.test.cjs`：离线检查。
- `product-workflow.cjs`：输入处理、规划与生成编排；`model-contracts.cjs`：模型输出规范化和语义边界校验；`stage-cache.cjs`：阶段记录与恢复。
- `qwen-provider.cjs`：百炼文字/视觉请求、脱敏及新旧图片恢复；`ark-image-provider.cjs`：原火山 Seedream 5 Pro 单图请求和调用记录。
- `content-plan.cjs`：新流程内容规划、证据校验、组件选择和两批排布；`structure.cjs`：离线旧规则；`plan.cjs`：结构校验与最终总图提示词。
- `compose.cjs` / `crop.cjs` / `download.cjs`：原组件组装、总图裁剪和导出。
- `server.cjs` / `index.html`：本机 API 与工作台。
- `product-workflow.test.cjs`：新流程及浏览器联调；其他测试保留旧功能回归。
- `planner.cjs`：历史离线规划说明及旧适配代码，服务不再调用旧模型。
