# 装修规划与素材批次实验

这版在已确认的 23 种固定组件前增加 AI 规划层，不修改 A13 或原应用。它让 AI 选择模块、安排顺序、提出素材方向，并把素材分成最多两张总图；程序校验方案、裁剪用户交回的总图、填入原组件。

## 启动

在本目录执行：

```sh
npm ci
npm start
```

打开 `http://127.0.0.1:5182`。端口可用 `PLANNER_PORT` 覆盖，结果默认写入本目录被忽略的 `output/runs/`，可用 `PLANNER_OUTPUT_DIR` 更换目录。

截图规划使用仓库根目录本机 `.env.local` 的 `ARK_API_KEY`、`ARK_RESPONSES_ENDPOINT`、`ARK_VISION_MODEL`，仅在服务端使用。也可以自己传入进程环境变量。没有配置时，“已存素材示例”和“其他 AI 接力入口”仍可用。

本目录单独安装 `@json-render/core` 与 Zod 4，不改变主应用的 Zod 3 依赖。

## 下载

素材填齐后，预览上方可下载 **完整 PNG 长图**（2 倍清晰度）或 **素材 ZIP**。下载只使用当前方案及已填入的图片，不调用 AI。缺图、占位素材或正在上传时会阻止导出，重新填图后下载会使用新内容。

ZIP 包含按模块和槽位编号的 PNG、各模块文字说明、可用 Excel 打开的中文对照表、JSON 对照信息及可离线打开的 `店铺预览/shop.html`。相同素材出现在多个模块时分别保留，方便逐项上传；它是手动装修素材包，不是微购一键导入格式。头像沿用预览中的现有占位图，实际装修时自行更换。原始截图、生图总图、模型响应和本机配置不打包。

PNG 通过 `playwright-core` 在独立无头浏览器中渲染已保存页面，自动尝试本机 Chrome、Edge、Playwright Chromium；不接入用户浏览器会话。已有 Chrome/Edge 无需另下载浏览器。其他部署环境可设置 `PLANNER_BROWSER_PATH` 为浏览器可执行文件绝对路径，或执行 `npx playwright-core install chromium`。没有可用浏览器时显示原因，ZIP 仍可用。

运行 `npm test` 检查导航分配、导出完整性、模块顺序和材料包内容。

## 可操作流程

1. **查看已存素材示例**：重用 A13 的图片，展示完整长页、模块用途、素材复用与两批生图计划。没有模型调用；少量局部裁图改为共用源素材，所以构图不承诺与 A13 全图逐像素一致。A13 原版保持不变。
2. **分析截图并规划**：只上传截图，规划 AI 自行决定风格与模块。长图规范化后用概览和最多四段局部图一次请求分析，不提取小商品图。输出不合格会显示原因，保存响应，不自动付费重试或替换成固定模板。
3. **批量生图**：每个批次已有完整 Prompt；交给可用的生图 AI。第二批同时提供第一批总图作为风格参考。这个入口不自动调用生图 API。
4. **裁剪填入**：按批次上传生成总图。程序检测洋红分隔带和实际画面边界，按目标比例裁剪，填回同一份固定 UI。裁剪不调用 AI。
5. **其他 AI 接力**：取得界面中的规划说明，与截图一起交给其他 AI；将返回 JSON 导入。它经过相同的目录、业务约束和素材引用校验。
6. **导航图库优先**：新截图规划会要求 AI 根据店铺方向填写 `navigationLibrary.style`；导入的新方案未指定时采用 `auto`。程序按导航标签精确匹配别名，从基础图库取图，立即填入并从实际生图批次中移除。原始 `plan.batches` 保留备用要求，界面和 `generation-batches.json` 才是实际需要生成、上传的批次。旧任务保持原先结果。

页面的“试用导航图库”提供简约通勤店与柔和日常店两份预设资料。当前只有上衣、衬衫、裤装、连衣裙四类，两种风格，共八张基础图；这不是新的截图识别结果。两份示例均复用四张图、无需新生图。建库本身使用内置 image_gen 生成两张总图，成本不计入后续单店复用。

`clean` / `warm` 由规划 AI 根据店铺方向选择；`auto` 只是按色板首色的明亮暖色倾向在两套图之间选择，不是完整的风格理解。未知分类、缺失文件、非方形素材、同一素材对应冲突分类，以及同时用于大海报的图片，都保留原生图计划。导航图仅可复用到导航及宽度不超过200px的品类示意橱窗。每个任务保存选择记录与素材副本，后续上传不重新更换已选图片。

运行 `npm test` 可检查分类别名、风格选择、图库装配、未知分类回退、缩减后的批次裁剪和旧方案兼容。已通过本机 API 与两个示例按钮的端到端检查；尚未新增真实截图规划模型调用，也未验证跨店铺风格识别准确率。

## 决策边界

- AI 决定店铺理解、模块用途和顺序、素材摄影方向、复用关系、批次分配。
- 程序守住模块白名单、每个组件的参数、数量、几何位置及素材引用。仅接受规划参数，没有任意 HTML/CSS/坐标入口。
- `@json-render/core` 提供目录提示词和结构校验；额外校验逐个模块参数和业务关系，不把结构正确等同于设计优秀。
- 上限为 24 个模块、12 张独立素材、2 张总图、每图6画面。模型需在上限内通过复用和并排行安排；并非每个店铺都必须用满。
- 五列导航单行5项；单列海报1张；极简招牌无背景图；轮播无指示点；三列橱窗使用完整行。
- 未知商品数用“—”，会员不冒认，橱窗价格留空。生成照片均是装修参考，不承诺实物保真。
- 模块内图片清晰度与构图仍需用户检验。分隔带丢失、数量错误、过度裁剪会明确拒绝，不猜测位置。对实际检测到的最外侧分隔色，在每边最多2至8像素的限额内清理，然后校正比例；内部残留分隔色仍拒绝。没有做商品语义定位。
- 风格一致性是共享约束和参考图提供的引导，不是模型保证。
- 素材 `direction` 分别说明用途、镜头、场景和局部配色；新规划要求填写，旧方案仍兼容。共享风格只统一色彩关系和摄影质感，参考上一批不等于复制包装、背景和构图。主视觉优先独立构图，导航与页尾小橱窗优先复用；重复大图及单一镜头会给规划提醒，提醒不等于图像质量评估。
- 新规划先填写 `artDirection`，明确整页主题、叙事顺序、1至3个贯穿要素和一个视觉重点；`direction.treatment` 区分环境、使用动作、静物、质地与图形构成。先生成代表主题的主要画面，再生成辅助素材；不要求每张都采用商品摄影。旧方案可省略新增字段，指定的视觉重点必须引用已有素材；同一表现方式的提醒仅检查计划，不代表实际画面评估。
- 通常最多裁掉30%画面；明确标为 `category` 且仅用于宽度不超过200px槽位的小素材可放宽至35%，超过30%时保留人工构图检查提醒。这只是在小尺寸用途下接受有限比例修正，不证明主体完整，也没有语义定位能力。
- 这是分阶段实验，不是已完成的“截图直接自动生图并发布”产品。素材下载、平台上传和真实轮播交互继续待定。

## 文件

- `catalog.cjs`：由已封装组件提取允许参数和图片槽位，补上选型用途。
- `plan.cjs`：方案结构、跨模块业务校验、批次 Prompt。
- `planner.cjs`：单次截图规划请求及其他 AI 可用的指引。
- `compose.cjs`：方案到原固定组件的适配。
- `crop.cjs`：按批次计划检测并裁剪素材总图。
- `example.cjs`：使用已有素材创建完整示例，执行 `npm run example`。
- `server.cjs` / `index.html`：独立的本机实验入口。
- `navigation-library.cjs` / `navigation-library/`：品类、风格与版本化基础图；包含生成提示词与来源记录。
- `navigation-example.cjs` / `navigation-library.test.cjs`：两份小型店铺资料与导航复用测试。
