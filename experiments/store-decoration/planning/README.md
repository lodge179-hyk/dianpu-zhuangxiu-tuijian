# 商品截图到装修模板

上传商品列表截图 → AI 识别商品 → 联网找风格 → 程序安排模块 → AI 编写逐图提示词 → 生图、裁剪、组装 → 下载。一轮只产生一套方案，没有候选选择。允许使用相似、同类型的示意商品，不要求复刻上传的具体 SKU。

本轮执行范围与验收记录见 [执行文档](../../../docs/product-image-workflow-execution-20261014.md)。原单方案模块规则的历史依据见 [结构执行文档](../../../docs/store-structure-execution-20261014.md)。本目录是独立实验，不修改主应用、平台组件几何或 A13。

## 启动与配置

在本目录执行 `npm ci`、`npm start`，打开 `http://127.0.0.1:5182`。结果默认写入被忽略的 `output/runs/`。`PLANNER_PORT` 和 `PLANNER_OUTPUT_DIR` 可覆盖端口和输出位置。

`npm start` 读取仓库根目录本机 `.env.local`，也可直接设置进程环境变量。密钥仅在服务端使用，不进入前端配置、素材 ZIP 或 Git。

| 配置 | 用途及默认值 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 必填，百炼 API Key |
| `PLANNER_VISION_MODEL` | 商品识别与逐图设计，默认 `qwen3.5-plus` |
| `PLANNER_SEARCH_MODEL` | 强制联网搜索，默认 `qwen-plus` |
| `PLANNER_IMAGE_MODEL` | 生成总图，默认 `qwen-image-3.0-pro` |
| `PLANNER_DASHSCOPE_BASE_URL` | 百炼服务根地址，默认 `https://dashscope.aliyuncs.com`，不要带 API 路径 |
| `DASHSCOPE_WORKSPACE_ID` | 可选，未覆盖根地址时使用北京业务空间域名 |

模型与凭据需属于同一地域，并已开通对应模型权限。配置存在不表示已验证账户额度或真实调用。不会静默切换模型；旧火山/豆包入口已返回 410，主流程没有旧模型回退。没有配置时仍可使用离线示例、完整方案 JSON 导入、手动总图上传和下载。

## 当前流程

1. 添加 1 至 6 张商品列表截图，可分次补充或移除。每张最多 10MB，合计 30MB，支持 PNG/JPEG/WebP。长截图提供概览及上下局部给识别模型。
2. 识别可见商品、1 至 5 个经营品类、证据图片和不确定信息。至少两种可辨识商品或款式才继续；单一品类有效。信息不足会提示补充，不为凑导航虚构品类，也不自动搜索或生图。
3. 单独调用联网搜索。只接受服务返回搜索记录中实际存在的来源；没有来源时停止。先保存服务返回的完整来源列表，再让模型只从提供的编号选择一个视觉方向，URL 由程序回填；不采用搜索模型在回答中自行写出的链接。风格选择只取得来源标题与网址，不把未读取的网页正文或图片细节说成事实。
4. 程序按现有规则确定模块、图片 ID、比例、用途与批次。AI 根据商品、来源及风格编写逐图内容和整套视觉方向，不能增删图片、改变用途或比例。主流程没有固定美妆/服装画面分支，也不自动套用旧导航图库。
5. 生图接口每批返回一张总图，最多两批。第二批附第一批总图，仅作为风格参考。实际发送的完整提示词可在页面展开查看；服务关闭提示词自动改写，避免所见和所发不一致。
6. 检测洋红分隔带，验证整批裁剪后再填入模块。失败不自动重试，保留已完成素材和已收到的总图。页面可明确点击“继续生成缺失素材”，只补失败批次；也可手动上传总图。继续生成会再次调用模型，可能产生费用。
7. 素材填齐后下载完整 PNG 长图或素材 ZIP，由用户判断图片与页面效果。

一轮正常任务包含四次语言/视觉模型请求（识别、搜索、选风格、逐图设计）和一至两次生图请求。界面展示阶段、商品理解、联网来源、选定风格、提示词、已填入素材和失败原因。关闭页面后服务仍执行，使用 `/?run=任务编号` 可查看保存进度；服务重启会标记中断，不自动重新调用。来源选择失败且已有有效资料时，可点击“沿用已有资料继续”，复用商品识别和搜索，从风格选择重做；不会重新上传截图或自动重复调用。

本地每个任务保留输入图片、识别与风格 JSON、逐阶段指令/响应、调用结果、方案、实际生图提示词、原总图和裁剪记录。只向浏览器开放必要结果文件，调用审计与响应文本不在静态下载白名单内。

## 模块与旧功能

仍使用现有 23 种固定组件及两种单方案组织规则；支持 1 至 5 个明确品类，典型结果为 4 至 6 个模块。四、五品类使用带文字的导航，少品类使用文字范围说明。主推事实与创意主题分开，生成的主题不能冒充经营事实。结构规则是当前设计假设，不是转化率结论。

旧任务及素材不改写。“先看示例效果”继续提供已有美妆成品和服装方案；它们不调用 AI，也不证明新提示词的真实生成质量。“试用导航图库”只演示已存四类服装素材的匹配。“离线结构试排”接受手填品类，但不检索、不生图；“其他 AI 接力入口”继续接受完整 JSON 和手动图片。

`POST /api/plan` 接受 `{images:[{name,data:"data:image/png;base64,..."}]}`，返回 202 和任务编号；兼容单张原始图片请求。`GET /api/runs/:id` 查询进度。`POST /api/runs/:id/generate` 明确继续缺失批次。`POST /api/runs/:id/resume-research` 从已有来源继续失败的风格选择。原推荐示例、手填资料、导入与下载接口仍保留。

## 下载

素材填齐后可下载完整 PNG 长图（2 倍清晰度）或素材 ZIP。下载不调用 AI。未完成任务、缺图或占位图阻止导出；重新填图后下载使用新内容。

ZIP 包含按模块/槽位编号的 PNG、模块文字说明、中文 CSV/JSON 对照及可离线打开的 `店铺预览/shop.html`。复用图片按各模块分别提供。这是手动装修素材包，不是平台一键导入格式；头像仍为占位图。原始截图、模型响应、本机配置和总图不进入 ZIP。

PNG 用 `playwright-core` 启动独立无头浏览器，不接入用户会话。自动尝试本机 Chrome、Edge、Playwright Chromium；部署时可设置 `PLANNER_BROWSER_PATH` 或执行 `npx playwright-core install chromium`。浏览器不可用时会说明原因，ZIP 仍可用。

## 验证与边界

运行 `npm test` 检查单方案约束、图库与导航文字兼容、下载、原生接口适配、多截图、搜索来源验证、失败不重试、部分成功保留和中断恢复。测试中的接口及总图均是受控模拟，不消耗真实模型额度，不证明视觉质量。设置 `PLANNER_BROWSER_PROOF=1` 后运行 `node --test --test-name-pattern="HTTP upload" product-workflow.test.cjs`，会另外使用本机 Chrome 验证网页上传、提示词展示、PNG/ZIP 下载及信息不足状态，截图保存在忽略目录。

- AI 负责商品理解、基于检索的风格提案与画面内容；程序守住组件、素材用途、比例、批次、裁剪与导出。
- 不支持任意 HTML/CSS 或坐标。结构上限 24 模块、12 素材、2 批次，每批最多 6 格；不是要求用满。
- 分隔带、图片数量、过度裁剪不合格时明确拒绝。没有商品语义定位，不能保证主体完整。
- 共享风格与参考图只提供引导，不能保证模型输出一致。识别准确率、风格适配度、生图质量和真实模型权限由用户后续用截图验证。
- 尚未实现平台发布、真实 SKU 保真、商品分类跳转或经营数据接入。

## 主要文件

- `product-workflow.cjs`：输入处理、识别/搜索/画面设计校验和生成编排。
- `qwen-provider.cjs`：百炼原生请求、调用记录、脱敏、图片下载与总图尺寸。
- `structure.cjs`：单方案模块规则；`plan.cjs`：结构校验与最终总图提示词。
- `compose.cjs` / `crop.cjs` / `download.cjs`：原组件组装、总图裁剪和导出。
- `server.cjs` / `index.html`：本机 API 与工作台。
- `product-workflow.test.cjs`：新流程及浏览器联调；其他测试保留旧功能回归。
- `planner.cjs`：历史离线规划说明及旧适配代码，服务不再调用旧模型。
