## 当前路径

AI 决定内容与设计 → 少量素材总图生成 → 程序识别分隔边界并裁剪 → 将素材填入固定组件 → 浏览器显示完整店铺参考页。

AI 后续负责选模块、组合和素材设计；固定 HTML/CSS 由组件库负责。模块选择规则目前仍待确定，不把当前人工辅助实验描述为已完成自动化。

本例使用两张生成素材总图，保留 16 张可复用素材及 1 张既有头像；同一素材可在多个槽位复用。展示 22 个模块实例、19 种样式、44 个图片槽位。商品与价格为演示内容，不代表客户真实 SKU。

## 已封装的样式

- 招牌：默认、经典、极简、全屏。
- 导航：每行四个、每行五个。
- 海报：单列、双列、三列、组合 1/2/3、横向滑动。
- 轮播：小图、中图、大图。
- 商品橱窗：单列、双列、三列、横向滑动。
- 文字：单行、多行、链接。

已确认约束：五列导航仅一行，单列海报仅一张；极简招牌不能自定义背景，其他招牌可以；轮播没有指示点。这里是静态装修参考，不含视频、真实轮播交互或商品列表页面。

## 重建 HTML

在仓库根目录执行：

```sh
node experiments/store-decoration/render.cjs
```

它读取已有 `page.json`、固定组件和本地素材，重建 `shop.html`。仅使用 Node 内置模块，不调用 AI，不修改业务应用或用户原始输出。素材裁剪需要仓库已有的 `sharp` 依赖。

若要复现素材裁剪，在根目录安装依赖后依次执行：

```sh
node experiments/store-decoration/a11-generate-and-crop/crop.cjs
node experiments/store-decoration/a13-complete-store/prepare-assets.cjs
node experiments/store-decoration/render.cjs
```

上述命令复用已保存的生成图片。重新生图需由执行 Agent 根据两个 `prompt.txt` 和记录自行调用可用模型；本快照没有嵌入模型凭证或自动生图接口。

`a13-complete-store/build.cjs` 是原实验的完整构建与浏览器检查脚本，仍保留原机器的 Playwright/Chrome 路径，仅作为来源记录。跨机器重建 HTML 请使用上面的 `render.cjs`，不需要运行该原始脚本。A9 的旧使用说明也属于历史记录，其中旧示例素材没有全部打包。

## 已有结果与边界

- 用户已认可 A12 示例的清晰度、比例，并评价 A13“整体效果还可以”。
- 原实验报告记录：174 个具名元素相对 A8 布局偏差为 0、素材全部加载；这是当时的检查结果，不是本次重新测试。
- 最终风格、AI 模块选择规则、截图自主分析、较低能力模型的决策与稳定性、客户素材下载和实际平台上传仍待推进。
- 不要求从截图中极小的商品图恢复可用素材；只在可辨识的范围内理解店铺信息。
- 本例适合装修参考，不承诺生成商品与客户实物一致。原工具未返回具体生图模型 ID 或费用，不据此估算成本。
