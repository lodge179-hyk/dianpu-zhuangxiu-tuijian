# 路线 A：利用真实 UI 数据验证低成本生图

负责人：原会话。状态：**计划已交接；用户最新要求暂不生图，本轮调用次数为 0。**

## 目标

验证能否在一次整图或少量大区块生成中，得到符合真实模块规则的装修参考图，并评估图中各素材区域能否用于后续下载。

不把“每个模块里的每张图片单独生成，再由程序固定 UI”作为本路线默认方案。程序复刻由 B 独立验证。

## 先回答的两个问题

1. 仅使用已知结构、位置、比例、小组件命名，能否让模型生成 UI 合格的页面？
2. 在调用次数保持很少的情况下，生成图内的素材分辨率、边界和内容是否足以单独交付？

第一个问题可暂时使用示例商品；第二个问题必须检查原生像素，不得以放大后的文件尺寸代替素材原始清晰度。

## 实验顺序（等待继续指示后执行）

### A1：一张图直接生成

- 使用 `data/comparison-case.json` 的小型共同样例与组件规格。
- 将数据整理成清晰的模块树和位置约束，避免直接塞入所有 23 种格式。
- 在一份 Prompt 中定义所有模块及小组件、顺序、列数、比例、哪些元素不允许出现。
- 同一次生成中安排全部图片内容；本阶段允许示例商品，必须标注为实验内容。
- 使用会话可用的内置生图能力，不默认调用项目 API；记录实际工具，模型型号未返回时写“未暴露”，不猜测。
- 一轮先调用一次并查看结果，不自动循环到满意。

### A2：为整图增加几何参考（按 A1 的结果决定）

可使用同一份数据对应的几何参考图，帮助模型理解比例。参考图的来源要标明；最终用于评估的仍是模型生成图，不能把程序渲染结果替换成模型输出。

这一项是后续可选实验，当前不生成参考图，也不要求 B 等待 A 才开始。

### A3：少量大区块／一张素材画布（备选）

- 若一张长图容纳不下，可按上半页／下半页等少量大区块生成后组合。
- 或研究一次生成包含多张独立图片的素材画布，再按边界分离；不得隐藏这与整页直接生图的区别。
- 建议先比较 1 次与 2 次调用的效果。这里不是已批准的付费预算，也不是必须调用 2 次。
- 一次生成多个文件也要记录输出图数量，不能把“一个请求”等同于“一张图的费用”。

## 必须记录的结果

| 项目 | 如何判断 |
| --- | --- |
| 模块完整性 | 是否漏模块、增模块、换顺序 |
| 内部组件 | 列数、圆图、标题、价格区、图标是否按指定存在 |
| 几何误差 | 同比归一化后比较边界、槽位比例、间距；没测量不要报百分比 |
| 文字 | 是否出现乱码、错字、编造文案 |
| 轮播点 | 必须没有 |
| 素材可分离 | 是否有跨槽位商品、文字越界、边缘粘连 |
| 下载清晰度 | 每个图片区域可获得多少原生像素，是否低于上传建议 |
| 效率与成本 | 实际生成调用、返回图数、重试次数、端到端耗时；费用未知就明确未知 |

单次完成只能说明一次样本效果，不能证明同样输入多次稳定。用户不要求完美，但结果必须诚实。

## 与 B 的边界

- A 可以只读 B 已交付的参考数据或结果，但不能修改 B 的工程、依赖或运行进程。
- 本路线的 Prompt、实验记录、图像放在原工作区自己的新目录，例如 `output/ui-image-generation-20261013/`。
- 不把 B 输出的 UI 图冒充 AI 一图生成，不以程序修好几何后的版本冒充原始模型准确度。
- 如果后续选择混合方案，原始图、修正图、调用次数分别保留，交由用户比较。
